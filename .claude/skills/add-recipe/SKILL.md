# /add-recipe

Turns an idea or a saved recipe into an ingredient list for the `/groceries` skill. This skill never calls the Woolies side of the `woolies` CLI itself (cart, search, orders). The one exception is reading the cupboard with `woolies cupboard list`, which only reads a local file.

Context: run `woolies config` to find the user's files. Read their grocery notes, the `CLAUDE.md` in the same folder as `cupboard_file` (preferences, things always at home), if it exists. Saved recipes are one file each in `recipes_dir`. Read and list them through the file-only `woolies recipe` commands (`list`; `show <slug|title words>` for parsed JSON plus the raw markdown; `match <slug>` for have/low/missing against the cupboard; `set <slug> --serves N --cost-per-serving X ... [--dry-run]` for header fields, keeping a `.bak`) rather than opening the folder. Only new recipe files, and edits `set` can't make (ingredients, method, notes, stockcodes), are written directly.

## Flow
1. **Find or pick.** For a new idea, search the web and choose a cheap, filling, homely recipe (a few options if the idea is vague). For an existing one, use `woolies recipe list` / `woolies recipe show <slug>`.
2. **Save.** Write new recipes to `<recipes_dir>/<slug>.md`: serves, ingredients, method, notes and source names (adapt, don't copy text verbatim). Show the user and let them tweak it.
3. **Build the list.** Combine ingredients across every recipe they are cooking: sum quantities, round up to sensible pack sizes, drop items in "Always at home". Run `woolies recipe match <slug>` per recipe for a first have/low/missing split, then check the cupboard with `woolies cupboard list` (or `--search <word>` per ingredient) and use its `size_qty`/`size_unit` to work out how much of each recipe item is already covered; only list the shortfall, and mark partly covered items ("have 700g mozzarella, need 400g: fine"). Ask about anything unclear (e.g. "is the chicken still in the freezer?"). If they say they already have something not in the cupboard, offer `woolies cupboard add "<item>" --source had --size 500g`. Use each recipe's `## Shopping list stockcodes` section as hints for the shop skill.
4. **Hand off.** Invoke the `/groceries` skill with the list (item, quantity needed, any known stockcode). It handles the cart, confirmation and totals.
5. **Update.** When `/groceries` reports the resolved stockcodes and prices, update the `## Shopping list stockcodes` section of each recipe so next time is faster. Remove stale notes.
6. **Cost.** Every recipe starts with a YAML header: `title`, `serves`, `cost_per_serving`, `total_cost`, `cost_basis: share of pack used`, `cost_calculated` (date). Work it out with read-only `woolies product <stockcode>` calls (one at a time, never in parallel) using each item's current `Price` and `PackageSize`. Cost each ingredient as the share of the pack the recipe uses (e.g. 300g of a 700g pack is 300/700 of the price; loose produce uses `UnitWeightInGrams`), items in "Always at home" and anything already owned (say which) cost $0, and ranged quantities use the midpoint. Add or refresh a `## Cost breakdown` section listing each line (edit the file directly), then update the header with `woolies recipe set <slug> --total-cost X --cost-per-serving Y --cost-calculated YYYY-MM-DD --dry-run` and, after checking the change, again without `--dry-run` (it also rewrites the `Total $X, $Y per serving` line). Do this when saving a new recipe and whenever stockcodes or prices are refreshed in step 5.
